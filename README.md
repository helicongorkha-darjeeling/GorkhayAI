# GorkhayAI

The website for GorkhayAI, an AI studio from Darjeeling that builds websites, AI booking bots and lead systems for hotels and homestays.

## Stack

- Next.js (App Router) + TypeScript + Tailwind CSS v4
- React Three Fiber + drei for the 3D Kanchenjunga hero
- GSAP ScrollTrigger (camera drift, How it works) and Framer Motion (tilt cards, form)
- Supabase for contact-form leads
- Deployed on Vercel

## Getting started

```bash
npm install
cp .env.example .env.local   # fill in the values
npm run dev
```

| Variable | Purpose |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Canonical URL for metadata, sitemap and OG images. Defaults to `https://gorkhayai.com`. |
| `SUPABASE_URL` | GorkhayAI Supabase project URL. |
| `SUPABASE_ANON_KEY` | Publishable / anon key. Row Level Security only lets it insert leads. |
| `NEXT_PUBLIC_WHATSAPP_NUMBER` | Digits with country code, e.g. `919800000000`. |
| `NEXT_PUBLIC_CONTACT_EMAIL` | Shown on the email button. Defaults to `ceo@gorkhayai.com`. |

Until the Supabase variables are set, the form returns a friendly "please WhatsApp or email us" message instead of saving.

## Leads table

Run `supabase/migrations/20261024000000_create_leads.sql` in the GorkhayAI Supabase project (SQL editor or `supabase db push`). It creates `public.leads` with insert-only access for the website key. Read leads in the Supabase dashboard and tick `contacted` after replying.

## Writing insights

Add a markdown file to `content/`. The file name becomes the URL (`content/my-post.md` → `/insights/my-post`).

```md
---
title: "Tool review: Something useful"
description: "One or two sentences for the card and search results."
date: 2026-11-01
category: Tool review   # or Blog
draft: false
---

Your post in markdown. Tables and GitHub-flavoured markdown work.
```

Posts appear on the home page grid, `/insights`, the sitemap, and get their own Open Graph image.

## The 3D hero

- The range is generated by `scripts/build-mountains.mjs` and saved as a Draco-compressed GLB in `public/models/kanchenjunga.glb` (about 36 KB; the build fails above 2 MB). Re-tune peaks there and run `npm run build:model`.
- The Draco decoder is self-hosted in `public/draco/`.
- The canvas is lazy-loaded with `next/dynamic` and only after the first interaction (or a few idle seconds on desktop), so it never delays first paint. It stops rendering when scrolled out of view.
- Phones with little memory or few cores, data-saver, slow connections, no WebGL, and `prefers-reduced-motion` all get the static posters in `public/hero/` instead. Add `?3d=1` or `?3d=0` to any URL to force either mode while testing.
- The posters are screenshots of the live scene. If you change the scene, capture new ones at 1920×1080 and 828×1472 and save them as WebP.
